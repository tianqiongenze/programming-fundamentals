### 知识四要素详解（V1.2深度版·与授课PPT同源）

**B01 异常是对象**
- 定义：异常=程序出错时扔出的'事故报告单'，类型名即线索
- 使用场景：读文件失败/除零——崩溃前的最后信号，接住就能救
- 应用实例：ZeroDivisionError/ValueError/FileNotFoundError
- 扩展与误区：误区：从最后一行往上读栈——错误类型→说明→行号倒着看
- 原理：异常是对象：Python出错时不静默崩溃，而是抛出携带类型/消息/回溯(Traceback)的异常对象沿调用栈向上找处理者
- 判断依据：程序'摔了能爬起来'的前提是接住异常对象——读懂Traceback是排错第一技能
- 逐行解释：Traceback自下而上读：最后一行是异常类型+原因，往上是出错调用链——NameError: name 'temp' is not defined 精确到行号
- 进阶优化：自定义异常class TempError(Exception)给业务语义；异常链raise ... from e保留原始现场

**B02 try/except/else/finally**
- 定义：try=试做/except=出事接住/else=没出事才做/finally=必做收尾
- 使用场景：采集主循环的防护壳——单点出错不能停整条产线
- 应用实例：try: read() except FileNotFoundError: 默认值
- 扩展与误区：误区：把大段代码塞进try——只包会出错的那几句，窄包才好查
- 原理：try是警戒区、except是处置区、else是无事发生的奖励区、finally是无论如何都走的收尾区——四段各司其职
- 判断依据：读文件/连设备/解析报文等'可能失败'的IO全部包try；except只接预期的类型，else放'成功才做'的后续
- 逐行解释：try: data=f.read() 可能炸；except FileNotFoundError: 兜底处置；else: parse(data) 成功才解析；finally: f.close() 无论成败都关门
- 进阶优化：Python 3.10可except (A|B)逗号改竖线；上下文管理器with能替代finally关资源——下一课细讲

**B03 精确捕获**
- 定义：except接具体类型=对症下药——一个except管一种病
- 使用场景：缺文件用默认值/类型错提示重输——不同错误不同对策
- 应用实例：except FileNotFoundError: … except ValueError: …
- 扩展与误区：误区：父类异常写前面会截胡后面所有——从小到大排
- 原理：精确捕获=except后面写明异常类型：FileNotFoundError/M ValueError/IndexError——对症下药，别一网打尽
- 判断依据：文件不存在与数据格式错是两种病：分开捕获分开处置——缺文件给默认配置，格式错记坏行跳过
- 逐行解释：except FileNotFoundError: print('用默认配置') 文件病；except ValueError: log_bad(line) 数据病——类型即分诊台
- 进阶优化：except Exception as e捕获变量e可打e.args看详情；但except Exception仍是宽网——生产代码按业务列明类型

**B04 禁裸except**
- 定义：裸except=把警报器全拆了——连Ctrl+C都吞程序杀不死
- 使用场景：新手最危险写法：except: pass——错误静默埋雷
- 应用实例：except Exception as e: print(e) 至少留痕
- 扩展与误区：误区：以为吞错程序更稳——恰恰相反，吞错让bug藏到最深处
- 原理：裸except(不写类型)会吞掉一切包括KeyboardInterrupt和SystemExit—— Ctrl+C都杀不死程序，是最危险的写法
- 判断依据：课堂铁律：except后面必须跟类型——裸except直接打回重写（工单评分扣分项）
- 逐行解释：except: 任何异常都进这里包括你想中断的——程序'看起来稳了'实则病根被掩盖；except ValueError: 才是处置你预期的病
- 进阶优化：最低限度写except Exception，并在体内logging.exception留全栈——'宽网+留痕'是裸except的唯一救赎

**B05 logging三级**
- 定义：logging=车间广播系统：INFO日常/WARNING注意/ERROR出事
- 使用场景：print混在结果里没法关——logging按级分流可开关
- 应用实例：logging.error(f'设备{code}连接失败')
- 扩展与误区：误区：忘basicConfig看不见输出——先配级别再打日志
- 原理：logging按级别分流：DEBUG排查细节、INFO正常运行、WARNING异常苗头、ERROR故障发生、CRITICAL停线事故——级别是分发开关
- 判断依据：print是无差别喊话（上线后删不干净）；logging是分级广播—— WARNING以上进日志文件，ERROR额外发通知
- 逐行解释：logging.basicConfig(level=logging.INFO, filename='run.log') 一次配置全局生效；log.warning('温度接近阈值:%s',temp) 占位传参免拼接
- 进阶优化：logging.exception('x')自动附全栈——except块里就用它；进阶按模块分logger、RotatingFileHandler日志轮转防爆盘

**B06 finally收尾**
- 定义：finally=无论成败必做的鞠躬——关文件断连接写统计
- 使用场景：资源不泄漏：采集崩了连接也得断干净
- 应用实例：finally: f.close() ——或直接用with替代
- 扩展与误区：误区：with open就是自动版finally——优先with，finally兜底非with场景
- 原理：finally无论try里return/break/异常还是正常跑完都执行——'无论如何都要做'的收尾专区（关文件/断连接/释放锁）
- 判断依据：采集程序断电/断网也要留下的现场清理——'程序摔了还能自己收拾残局'的保障段
- 逐行解释：finally: conn.close() 即使except里return了，连接照样关——这就是'病历本'之外的安全带
- 进阶优化：现代Python优先用with open(...) as f自动收尾（上下文管理器），finally留给with罩不住的场景

## 避坑
- `except:` 裸捕获吞掉KeyboardInterrupt → 禁止；
- 日志中文乱码 → logging.FileHandler(..., encoding="utf-8")；
- 在except里pass什么都不做 → 至少记录ERROR并继续。
