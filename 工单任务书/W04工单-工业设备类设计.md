### 知识四要素详解（V1.2深度版·与授课PPT同源）

**B01 类与实例**
- 定义：类=图纸，实例=按图纸造出的每台泵——一图多产品
- 使用场景：一类设备抽象成类，每台设备是独立实例
- 应用实例：class Device: … ；d1=Device('PUMP-03')
- 扩展与误区：误区：改d1不影响d2——各实例各一份属性，图纸本身不存温度
- 原理：类是图纸（定义属性与方法的模板），实例是照图纸造出的设备——一张图纸可造N台设备，每台独立持有自己的数据
- 判断依据：设备数量多、字段重复出现（十台注塑机各有一套编号/温度）时用类建模；单次临时数据用字典即可
- 逐行解释：class Device: 定义图纸；d1=Device('P3') 造第一台；d2=Device('P5') 造第二台——d1、d2互不干扰各存各的
- 进阶优化：类属性vs实例属性：所有设备共享的常量（如厂区码）放类属性，每台不同的放实例属性——省内存且语义清晰

**B02 __init__与self**
- 定义：self='我自己'；__init__=出厂设置，造时自动执行
- 使用场景：出厂时写死编号型号——构造即初始化
- 应用实例：def __init__(self, code): self.code=code
- 扩展与误区：误区：方法漏写self→TypeError——调用时Python自动传实例
- 原理：__init__是构造器：造实例时自动执行的第一段代码；self就是'当前这个实例自己'——Python把实例显式传进方法
- 判断依据：凡是'每台设备出生就该有的字段'（编号、状态）全部写进__init__——出生即建档
- 逐行解释：def __init__(self, dev_id): 签名里self必在第一位；self.dev_id=dev_id 把传入值存进这台设备——d1=Device('P3')时self就是d1
- 进阶优化：self不是关键字是约定名（别改成别的）；__new__造对象、__init__配对象——进阶了解两者分工

**B03 实例属性**
- 定义：属性写在__init__里=每台设备自己的小本本
- 使用场景：两台泵温度不同互不干扰——独立内存
- 应用实例：d1.temp=78.5 与 d2.temp=81.0 各存各的
- 扩展与误区：误区：写在类下的属性是全员共享公告栏——改一处全变，慎用
- 原理：实例属性存在每台设备自己的__dict__里——同名属性各改各的互不影响，这是'实例隔离'的底层保障
- 判断依据：判断'这个数据是每台各一份还是全局一份'：各一份→实例属性，全局一份→类属性
- 逐行解释：d1.temp=78.5 只改1号机；d2.temp不变——print(d1.__dict__)能直接看到这台设备的名值表
- 进阶优化：slots=('dev_id','temp')锁死属性名单省内存防手滑加错属性名；属性查找顺序：实例→类→父类（MRO链）

**B04 方法调用**
- 定义：方法=类里装的技能；d.start()=让这台设备执行
- 使用场景：启动/停止/读数——行为与数据装在一起
- 应用实例：def start(self): self.running=True → d.start()
- 扩展与误区：误区：方法里改self属性=改这台设备状态——这正是对象的 value
- 原理：方法调用d1.start()的真相：Python翻译成Device.start(d1)——self接收的就是点号前面的实例
- 判断依据：动作类逻辑（启动/停止/自检）写成方法而非外部函数——数据和行为绑在一起才是对象
- 逐行解释：d1.start() 点号即'对这台设备执行'；等价Device.start(d1) 显式传实例——看懂这个等价，self的谜团就解了
- 进阶优化：classmethod Alternative构造器（Device.from_csv(row)）、staticmethod纯工具函数——三种方法按'要不要实例'选型

**B05 __str__可读化**
- 定义：__str__=设备的自我介绍：print时说人话不报内存地址
- 使用场景：调试台账输出——不再看到<__main__.Device at 0x…>
- 应用实例：def __str__(self): return f'{self.code} {self.temp}℃'
- 扩展与误区：误区：__str__必须return字符串——return数字也TypeError
- 原理：__str__定义print(对象)时显示什么——默认是一串内存地址，重写后人一眼读懂设备状态
- 判断依据：调试与巡检时print(d)想直接看到'P3 运行中 78.5℃'——就该重写__str__
- 逐行解释：def __str__(self): return f'{self.dev_id} {self.status} {self.temp}℃'——print(d1)立刻输出可读台账行
- 进阶优化：__repr__给开发者看（交互式回显），__str__给用户看（print）——两个都写才是专业做法

**B06 状态校验**
- 定义：状态机=设备只走合法路线：停机才能启动，运行中拒重复
- 使用场景：把'不许重复启动'规则关进类里——外部想错都难
- 应用实例：if self.running: print('已在运行') else: 启动
- 扩展与误区：误区：校验散在类外各处=规则失控——封装的意义就在收权
- 原理：状态校验=方法入口先检查合法性再干活：已运行的设备再start()应被拒绝——把'不该发生的操作'挡在状态机门口
- 判断依据：任何带状态的对象（设备启停、登录登出）的方法都该先验状态——防重复启动/非法停止
- 逐行解释：def start(self): if self.status=='running': print('已在运行'); return —— 早返回挡住非法调用，后面的启动逻辑才执行
- 进阶优化：用异常替代print（raise RuntimeError('设备已运行')）让调用方必须处理；进阶用Enum定义状态枚举防字符串手滑

## 避坑
- 方法漏写 self 参数 → 调用时报"多传了一个参数"；
- 属性直接在类体定义被所有实例共享 → 实例属性写在 `__init__` 里；
- `d.start` 少括号 → 拿到方法对象而不是调用。
