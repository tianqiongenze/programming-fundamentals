# 02 架构说明（TOGAF 四域视角）

> 项目：多设备巡检循环模拟

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 排班从'平均用力'转为'按告警频次倾斜'，优先盯问题设备 |
| 数据架构 | 设备×周期的巡检矩阵（dict of list）；每台设备的告警计数与温度轨迹 |
| 应用架构 | core 生成温度轨迹并判定；pipeline 组织双层循环、聚合统计 |
| 技术架构 | Python 3.12 + conda py02；仅标准库（random 种子固定）；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 温度轨迹生成 + 告警统计 | `series()/count_alarms()` |
| `pipeline.py` | 设备×周期双层循环 | `run(cfg, out_dir)` |

## 依赖方向
```
run.py  →  pipeline  →  core（纯函数，零依赖）
               ↓           ↑
            io_utils ←── report
               ↑
            config（YAML 驱动）
```
**规则**：下层不得反向依赖上层；`core` 不 import `io_utils`（保持可单测）。

## 关键质量属性
- **可测试性**：core 为纯函数 → 单测无需 mock 文件系统
- **可配置性**：阈值全部外置 YAML
- **可复现性**：种子固定于配置
