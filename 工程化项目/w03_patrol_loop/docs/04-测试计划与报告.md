# 04 测试计划与报告（GB/T 15532《计算机软件测试规范》）

> 项目：多设备巡检循环模拟（工单 W03《工业实时告警系统Ⅱ》）

## 1. 测试策略
| 层级 | 方法 | 目标 |
|---|---|---|
| 单元测试 | pytest，`core` 判级/统计/循环函数 | 覆盖正常/边界/异常三档 |
| 集成测试 | pipeline 端到端（临时目录） | 设备×周期双层循环→汇总链路正确 |
| **验收测试** | `tests/test_acceptance.py` 逐档断言 | 工单 D/C/B/A 四档可量化复现 |
| **规范率实测** | `stylecheck.py`（pycodestyle 2.14，缺失时降级内置体检器） | 每档"规范率≥N%"有真实数字 |
| 回归 | `pytest -q` 全量 | 任一改动不破坏既有行为 |

## 4. 缺陷记录
| 编号 | 描述 | 处置 |
|---|---|---|
| D-01 | 判级逻辑内联在循环里，无 `check_device(d)`/`alarm()` 具名函数（工单任务1/2） | 抽为两个具名函数，循环只负责调度 |
| D-02 | 设备清单由代码随机合成，与工单"列表套字典"口径不符 | 改为 `config/rules.yaml` 的 3 台设备字典 |
| D-03 | 巡检周期 12，工单点名 10 | 改为 `n_cycles: 10` 并被测试锁死 |
| D-04 | 无 while 版本（工单任务5 选做） | 新增 `while_one()`/`patrol_while()`，三重退出条件 |
| D-05 | 无 A 档函数化收益对比交付物 | 新增 `docs/09-函数化收益对比-W02到W03.md`，报告与测试双向引用 |
| D-06 | 常量曾命名为中文 `收益对比`，与工单 B06"中文变量名同事抓狂"自相矛盾 | 改名 `DEFAULT_A_TIER_DOC`，路径改由 `config/rules.yaml` 提供 |
| D-07 | `patrol_while()` 实测 28 行，超 B 档 15 行门槛 | 拆出 `while_one()` 承载循环体，`patrol_while()` 只做调度 |
| D-08 | E127 续行多缩进 6 处（pipeline 分节字符串） | 各分节文本提为局部变量，实测归零 |

> 本轮无遗留缺陷。
