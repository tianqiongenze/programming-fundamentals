# 09 函数化收益对比（W02 → W03）·工单 A 档交付物

> 工单 W03 优(A) 档要求：**达 B 且重构 W02 代码对比说明"函数化收益"**。
> 本文就是那份对比：同一段告警逻辑，W02 的写法 vs W03 的写法。

## 1. 同一条判断，两代代码长什么样

### W02（单次判断·散装 if）

```python
temp = 96.0
press = 0.66
if temp >= 95:
    if press >= 0.65:
        print("[紧急] 温度 %.1f℃ 压力 %.2fMPa" % (temp, press))
    else:
        print("[停机] 温度 %.1f℃" % temp)
elif temp >= 80:
    ...                       # 每台设备都要重抄一遍这段
```

### W03（函数封装·两个具名函数）

```python
def check_device(d, warn=None, danger=None):   # 只做判级，不输出
    ...
    return "emergency"

def alarm(level, msg):                         # 只做输出，不判级
    return "[%s] %s" % (LEVEL_NAME.get(level, "未知"), msg)

for dev in devices:                            # 外层设备
    for cycle in range(n_cycles):              # 内层 10 个周期
        level = check_device(dev)              # ← 判级只写一次
        print(alarm(level, "%s 第%d周期" % (dev["code"], cycle + 1)))
```

## 2. 收益量化（可复核，不靠感觉）

| 对比维度 | W02 散装 if | W03 函数化 | 收益 |
|---|---|---|---|
| 判级逻辑出现次数 | 每台设备抄一遍（3 台 = 3 处） | `check_device` 1 处 | 改阈值只改 1 处 |
| 输出格式出现次数 | 每个分支一个 `print` | `alarm()` 1 处 | 换前缀/加时间戳只改 1 处 |
| 单函数最长行数 | 主块 18 行（含 4 层缩进） | ≤15 行（工单 B 档实测） | 一屏读完，不用上下滚 |
| 可测试性 | 只能整段跑，靠肉眼看输出 | `check_device({"temp":96})` 直接断言 | pytest 覆盖 8 个级别组合 |
| 新增一台设备 | 复制粘贴整段 if | 列表加 1 个 dict | 零复制 |
| 周期数变更 | 无（W02 只跑一次） | `n_cycles` 配置项 | 改配置不改代码 |

> 上表的"≤15 行"由 `tests/test_acceptance.py::test_b_tier_function_within_15_lines`
> 用 `inspect.getsource()` 实测断言，不是口头声明。

## 3. 三个"重复"分别被谁消掉了

1. **判级重复** → `check_device(d)`：阈值优先级"显式入参 > 设备自带 > 全局默认"，
   于是"同类同阈值、异类各自一套"（W02 B04 的嵌套判断场景）在配置里写就行。
2. **输出重复** → `alarm(level, msg)`：级别到文案的映射收进 `LEVEL_NAME` 字典，
   班长要改"[停机]"为"[红色]"时只动一个字典。
3. **循环重复** → `patrol()` 把"外层设备 × 内层周期"封成一次调用，
   W03 的 `while` 版（`patrol_while()`）只改循环骨架，判级与输出原样复用——
   这就是"函数化之后，换实现不换接口"的直接体现。

## 4. 代价（诚实说明，别只讲好处）

- 函数调用有开销：本项目 3 台 × 10 周期 = 30 次调用，量级完全无所谓；
  十万级样本时再考虑把判级向量化（numpy）或缓存阈值。
- 参数变多：`check_device(d, warn, danger)` 比散装 if 多两个入参，
  换来的是"阈值可以从设备字典里自带"，值得。
- 调试路径变长：出错时要跳到被调函数里看——所以每个函数都留了 docstring，
  并把 `exit_reason` 一类过程量写进 `output/report.txt`，留痕可追溯。

## 5. 下一步（W04 预告）

设备字段越加越多（编号/名称/状态/温度/压力/阈值/维护态），字典开始管不住"字段拼写错误"。
W04 用 `class Device` 把这些字段与行为收进对象，`check_device(d)` 将升级为
`device.check()`——函数化的收益在对象化之后继续保留（方法就是绑在数据上的函数）。

## 6. 机器实测数字（工单优(A) 档判定口径，run.py 每次重跑）

上文的"收益"不是修辞——`src/patrol_loop/measure.py` 用 AST 同时扫 W02 与 W03
的 `core.py`（W02 源码路径外置在 `config/rules.yaml` 的 `tiers.A.w02_core`），
数字随 `output/report.txt` 的「验收档位判定（实测）」段落每次重新生成：

| 实测维度 | W02 | W03 | 说明 |
|---|---|---|---|
| 判级用 `≥` 比较出现点数 | 13 处 | 6 处 | AST 数 `Compare(GtE)`：判级收敛后重复比较大幅减少 |
| 判级函数个数（名字含 level/check） | 3 个 | 1 个 | `temp_level/press_level/nested_level` → `check_device` |
| core.py 有效行数 | 106 行 | 113 行 | W03 多出的行花在循环封装与 while 有界版上（能力变强、行数微增，合理） |
| 最长函数体行数 | — | 15 行（`patrol`/`while_one`，恰好压线） | B 档"每个函数≤15 行"由 AST 逐函数实测 |
| docstring 覆盖率 | — | 12/12（100%） | "注释清晰"的可机器判定部分 |
| 循环实跑样本 | — | 3 台 × 10 周期 = 30 | D 档"循环跑通"的实测证据 |
