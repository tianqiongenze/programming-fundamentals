# 02 架构说明（TOGAF 四域视角）

> 项目：质量日报生成

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 把分散在系统里的产线数据变成一份可打印、可归档的日报，供班组早会使用 |
| 数据架构 | KPI 行（line/planned/produced/good/oee）→ 派生合格率/达成率 → PDF 报表 |
| 应用架构 | core 计算派生指标并渲染报表行；pipeline 生成 txt + PDF（含降级） |
| 技术架构 | Python 3.12 + conda py02；reportlab（可选，缺失自动降级）；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 派生指标计算 + 报表渲染 | `derive()/render_table()` |
| `io_utils.py` | 文本/JSON 落盘 | `write_text()/write_json()` |
| `pipeline.py` | KPI→报表→PDF（含降级） | `run(cfg, out_dir)` |

## 依赖方向
```
run.py  →  pipeline  →  core（纯函数，零依赖）
               ↓           ↑
            io_utils ←── report
               ↑
            config（YAML 驱动）
```
**规则**：下层不得反向依赖上层；`core` 不 import `io_utils`（保持可单测）。

## 关键质量属性
- **可测试性**：core 为纯函数 → 单测无需 mock 文件系统
- **可配置性**：阈值全部外置 YAML
- **可复现性**：种子固定于配置
