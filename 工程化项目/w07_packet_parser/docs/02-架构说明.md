# 02 架构说明（TOGAF 四域视角）

> 项目：工业报文解析器

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 多品牌设备报文统一入库，为上层平台屏蔽协议差异 |
| 数据架构 | 原始报文（字符串）→ 统一读数对象（id/temp/press）+ 未知格式隔离区 |
| 应用架构 | core 为每种格式一个解析器（策略模式）+ 路由器；pipeline 统计格式分布 |
| 技术架构 | Python 3.12 + conda py02；仅标准库（json）；pytest |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 格式路由 + 各格式解析器 | `parse()/parse_json()/parse_csv()/parse_kv()` |
| `pipeline.py` | 批量解析→格式统计 | `run(cfg, out_dir)` |

## 依赖方向
```
run.py  →  pipeline  →  core（纯函数，零依赖）
               ↓           ↑
            io_utils ←── report
               ↑
            config（YAML 驱动）
```
**规则**：下层不得反向依赖上层；`core` 不 import `io_utils`（保持可单测）。

## 关键质量属性
- **可测试性**：core 为纯函数 → 单测无需 mock 文件系统
- **可配置性**：阈值全部外置 YAML
- **可复现性**：种子固定于配置
