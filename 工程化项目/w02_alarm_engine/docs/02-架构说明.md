# 02 架构说明（TOGAF 四域视角）

> 项目：设备多级告警判定引擎

| TOGAF 域 | 本项目答案 |
|---|---|
| 业务架构 | 把'靠人巡逻发现险情'变为'程序自动喊疼'，压缩漏报窗口，守住安全底线 |
| 数据架构 | 读点为时序值对象（ts/temp/press）；告警为事件对象（level/原因/是否去重）；规则阈值全部外置 YAML，输出告警事件 JSON |
| 应用架构 | core 做单点判定+多条件组合+去重；pipeline 顺序消费读数序列、统计告警分布 |
| 技术架构 | Python 3.12 + conda py02；仅标准库；pytest；CLI |

## 分层与模块职责
| 模块 | 职责 | 关键接口 |
|---|---|---|
| `core.py` | 告警引擎：判定/组合/升级/去重 | `judge()/dedup()` |
| `pipeline.py` | 读数序列→告警事件流 | `run(cfg, out_dir)` |

## 依赖方向
```
run.py  →  pipeline  →  core（纯函数，零依赖）
               ↓           ↑
            io_utils ←── report
               ↑
            config（YAML 驱动）
```
**规则**：下层不得反向依赖上层；`core` 不 import `io_utils`（保持可单测）。

## 关键质量属性
- **可测试性**：core 为纯函数 → 单测无需 mock 文件系统
- **可配置性**：阈值全部外置 YAML
- **可复现性**：种子固定于配置
